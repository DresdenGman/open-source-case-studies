# Case Study: StatsForecast — Three Pull Requests, Three Merged

## Context

StatsForecast is Nixtla's high-performance library of statistical forecasting algorithms — ARIMA, ETS, Theta, CES, and their automatic variants. In real-world decision systems, a point forecast is only half a deliverable; the uncertainty envelope around it is what capital allocation, capacity sizing, and risk limits actually depend on. My work targeted this exact margin: expanding prediction interval capabilities and unlocking runtime performance on core parametric models.

## The three merged pull requests

- **[#1175 — Add `conformal_error` prediction intervals method](https://github.com/Nixtla/statsforecast/pull/1175)**. StatsForecast offered distribution-based conformal intervals; I implemented its companion, building prediction bands directly from quantiles of the conformity scores. Review provided vital mathematical scrutiny: my initial draft kept the method gated behind `allowed_methods`, had an inverted column ordering, and contained an incorrect quantile cut. I corrected the formula from 1−α/200 to lv/100 — the correct quantile level for absolute conformity scores, matching the split-conformal convention in mlforecast. I replaced loose asserts with exact-value checks against `np.quantile`. When the maintainer asked for an end-to-end model test, I flagged that I had not yet built one; he wrote and added the test himself before merging. CodSpeed reported no measurable change across its 38 benchmark checks.
- **[#1241 — Expose a fixed `theta` parameter](https://github.com/Nixtla/statsforecast/pull/1241)** (closes #860). The low-level `auto_theta` core supported a fixed θ parameter to bypass expensive parameter searches, but public constructors (AutoTheta, OptimizedTheta, DynamicOptimizedTheta) never exposed it. For pipelines where optimal parameters are already calibrated, users paid unnecessary optimization overhead on every series. I threaded an optional θ through public constructors, fitting routines, direct simulation, and the memory-efficient forecasting path, validated against the same finite [1, 10^10] range the internal optimiser uses, while preserving backward compatibility. 235 tests passed across the new regression file plus the existing Theta and model suites, with fit/predict parity between the regular and memory-efficient paths. In a local five-run benchmark on a 1,440-point synthetic seasonal series, median fit time dropped from 19.6 ms to 4.62 ms at θ=2.5 — an indicative local measurement demonstrating the throughput unlocked when redundant estimation is bypassed.
- **[#1176 — Add `py.typed` marker](https://github.com/Nixtla/statsforecast/pull/1176)** (closes #1121). A one-file packaging fix: without the PEP 561 marker, type checkers treated the entire installed package as untyped. I validated that the marker file bundled correctly into both built wheels and source distributions, ensuring downstream codebases receive full typing support.

## What it demonstrates

This work tackled algorithmic modeling, API design, and statistical foundations. The conformal-interval PR received substantive mathematical review: the maintainers audited the underlying equations, caught an incorrect quantile calculation, and required an exact statistical fix before integration, while adding the end-to-end validation test directly. I focus on understanding the mathematics behind the tools, respecting upstream maintainers' domain expertise, and delivering verifiable production features.

Further work: a merged FreDF loss contribution in NeuralForecast; additional StatsForecast PRs under review.
