# Case Study: SALib — Six Pull Requests, Six Merged

## Context

SALib is an open-source Python library for global sensitivity analysis: Sobol' indices, Morris screening, Shapley effects — decomposing complex systems to see which inputs drive an output and how much variance each explains. My research models power-grid stress under extreme weather and audits the structural assumptions behind trading backtests. In both domains, the central question is never just what a model outputs, but which underlying assumptions drive that result. That is the fundamental sensitivity-analysis question, and it is why I chose to contribute directly to SALib.

## How the engagement started

Issue-first, with small things I could prove. The first three PRs addressed existing defects I reproduced locally before writing a line of code — one Sobol' correctness bug and two nondeterministic test failures, including one that required 250 unseeded repetitions to isolate 5 subtle failures. Establishing technical credibility on core bugs first gave me the foundation to take on the maintainers' open feature request: bringing a missing, mathematically complex method from the literature into production.

## The six merged pull requests

- **[#678 — Fix Sobol analysis for partially constant multi-output columns](https://github.com/SALib/SALib/pull/678)** (fixes #619). A scalar `np.ptp(y)` check missed constant columns in multi-output analyses and produced invalid indices. Fix: robust per-column zero-variance handling using `np.divide` with a `where=` condition, supported by regression tests. The maintainer extended this exact pattern to the second-order calculations in review before merging.
- **[#685 — Seed the discrepancy test sample](https://github.com/SALib/SALib/pull/685)** (closes #681). `test_discrepancy` was intermittently failing due to an unseeded Latin hypercube sample. I isolated the nondeterminism across 250 unseeded repetitions (5 failures), anchored the seed, and verified 20/20 focused passes to eliminate CI flake.
- **[#688 — Seed the delta SVM regression test](https://github.com/SALib/SALib/pull/688)** (closes #687). The test bled state from earlier runs because the delta bootstrap relied on NumPy's legacy global RNG. I wired in the existing `set_seed` fixture without touching external interfaces. Verified on Python 3.10 and 3.14 — 17 targeted tests passed in both, and estimates were identical under two different ambient seeds.
- **[#686 — Add Goda Shapley effects method](https://github.com/SALib/SALib/pull/686)** (refs #682). A complete from-paper implementation of the Goda et al. Shapley-effects estimator, which builds N(D+1) independent input samples and computes analytical confidence intervals for independent inputs. Shipped with CLI support, full documentation, worked examples, and Ishigami regression tests. In review, the maintainer vectorised my core loop — a 15–50× speedup he contributed, not me.
- **[#693 — Fix non-finite Morris samples for unbounded distributions](https://github.com/SALib/SALib/pull/693)** (closes #515). Morris trajectories pass through unit-interval endpoints, causing unbounded inverse CDFs to silently return `inf`/`-inf` samples. I deliberately did not "fix" the shared scaler — that would have silently changed every sampler's requested distribution. Instead, I designed a targeted Morris-specific guard that raises an error naming the affected parameters and points users to `truncnorm`. Verified across normal and lognormal distributions against a bounded control.
- **[#694 — Add retained resamples to Morris analysis](https://github.com/SALib/SALib/pull/694)** (closes #579). An opt-in `keep_resamples` feature exposing bootstrap `mu_star` replicates for empirical ranking and parameter robustness audits. To preserve structural integrity, I drew a single shared resample-index matrix outside the parameter loop so every retained row represents a coherent, synchronized bootstrap replicate. 245 passed, 1 xfailed, including regression coverage of the opt-in contract and grouped aggregation. The maintainer brought the original feature requester into review to verify the interface solved the production use case.

## What it demonstrates

Six submissions, six merges, built on rigorous mathematical inquiry rather than cosmetic fixes. Review materially strengthened each contribution: the maintainer expanded my Sobol' logic to second-order calculations, vectorised the Goda core loop for order-of-magnitude performance gains, and verified the Morris bootstrap design directly with the community member who requested it. My operating pattern across every codebase: reproduce the issue first, preserve existing API contracts, state empirical verifications transparently, and see technical critique through to clean production code.
